# Лабораторная работа 3–4

Текстовый редактор на C++17 и Qt Widgets. Реализация обеих частей методички
«Разработка текстового редактора средствами Qt».

## Быстрый запуск

Из корня репозитория **BMSTU**, Windows PowerShell 5.1 или PowerShell 7:

```powershell
.\2_course\OOP_Labs\sem2_lab3-4\run.ps1
```

Сборка и автоматические проверки без открытия окна:

```powershell
.\2_course\OOP_Labs\sem2_lab3-4\run.ps1 -Test -BuildOnly
```

После сборки можно запускать приложение напрямую:

```powershell
.\2_course\OOP_Labs\sem2_lab3-4\build\sem2_lab34_text_editor.exe
```

Если терминал уже открыт в папке `sem2_lab3-4`, достаточно:

```powershell
.\run.ps1
```

Для обычного повторного запуска без пересборки откройте
`build\sem2_lab34_text_editor.exe` двойным щелчком в Проводнике Windows.
Каталог `settings` и библиотеки рядом с exe нужны для его работы:
переносить один exe отдельно от остального `build` нельзя.

Нужен комплект Qt 6.5+ с Widgets, Xml, Test и компилятором C++17.
Проверяемый локальный комплект: Qt 6.12.0 MinGW, CMake, Ninja,
`C:\Qt\Tools\mingw1310_64`. Для другого расположения используйте параметры
`-QtRoot` и `-QtTools`. Скрипт меняет PATH только на время своей работы,
размещает DLL и плагины через windeployqt, включает русский перевод Qt.
Перед повторной сборкой сохраните документы и закройте редактор:
скрипт не завершает работающий редактор автоматически.

Прямой запуск поддерживает пути файлов в аргументах командной строки.
Каталог `build` исключён из Git общим `.gitignore` репозитория.

## Как пользоваться редактором

### Открыть или создать документ

1. Нажмите «Файл → Открыть…», Ctrl+O или кнопку с папкой на панели.
2. Выберите текстовый файл. Для демонстрации подсветки откройте
   `examples\demo.cpp`, для обычного текста — `examples\notes.txt`.
3. Документ откроется в отдельной вкладке. Переключайтесь щелчком по вкладкам
   или по именам в панели «Открытые документы» слева.
4. Для нового текста нажмите «Файл → Новый», Ctrl+N или кнопку с листом.

Файлы `.cpp`, `.h`, `.hpp` и другие расширения из XML получают подсветку.
У нового документа она появится после первого сохранения с нужным расширением.
Повторное открытие того же файла переключает существующую вкладку.

### Изменить и сохранить текст

1. Щёлкните внутри рабочей области и вводите текст. Звёздочка `*` рядом
   с именем означает наличие несохранённых изменений.
2. Для копирования, вырезания и вставки используйте меню «Правка»
   или Ctrl+C, Ctrl+X, Ctrl+V. Ctrl+A выделяет весь текст.
3. Нажмите Ctrl+S или кнопку с дискетой. Для нового документа выберите
   каталог и укажите полное имя с расширением, например `заметки.txt`.
4. Для копии под другим именем выберите «Сохранить как…» или Ctrl+Shift+S.
   При смене расширения подсветка обновится автоматически.
5. Ctrl+Alt+S или кнопка с двумя дискетами сохраняет все изменённые
   и новые документы. Если для нового документа отменить выбор имени,
   операция остановится.

После успешной записи звёздочка исчезает. Внизу на 5 секунд появляется
имя документа и каталог сохранения. Справа постоянно видны строка и столбец.

### Панели, закрытие и выход

- «Вид → Показать проводник» включает дерево каталогов: раскрывайте папки
  стрелками и щёлкайте по файлам для открытия. Ctrl+Shift+E скрывает
  или показывает эту панель.
- «Вид → Показать обозреватель открытых документов» и Ctrl+Shift+D
  управляют списком вкладок. Закрытие панели её крестиком не закрывает документы.
- Ctrl+W, Ctrl+F4 или крестик вкладки закрывает текущий документ.
  Если он изменён, можно сохранить, отказаться от сохранения
  (кнопка «Отклонить» в стандартном русском переводе Qt) или выбрать «Отмена».
- «Файл → Закрыть все» или Ctrl+Shift+W последовательно закрывает вкладки.
- Ctrl+Q или крестик главного окна завершает приложение. Для изменённых
  документов сначала открывается таблица с именами и расположением:
  «Сохранить все» записывает изменения, «Не сохранять» разрешает выход,
  «Отмена» возвращает в редактор.
- Если отменить диалог выбора имени или возникнет ошибка записи,
  выход отменяется: документы остаются во вкладках.

## Архитектура и владение объектами

| Класс | Ответственность | Основание |
| --- | --- | --- |
| `MainWindow : QMainWindow` | Вкладки, действия, панели, выбор файлов и закрытие | Лекция 4, слайды 3–13, 21–27, 39–42 |
| `DocumentEditor : QTextEdit` | Текст, путь, чтение и сохранение; без диалогов | DocWindow из лекции 4, слайды 22–24 |
| `SyntaxSettingsReader` | Абстрактный интерфейс стратегии чтения настроек | Требование методички; виртуальный интерфейс аналогичен MeshLoader из ЛР1 |
| `XmlSyntaxSettingsReader` | Чтение XML и проверка правил | Требование методички; DOM уже применялся в ДЗ2 |
| `SyntaxDefinition`, `HighlightRule` | Независимые от XML данные о языке и правилах | Контейнеры, строки, regex из лекции 2 о Qt |
| `SyntaxHighlighter` | Применение правил к блокам QTextDocument | Пример Qt из литературы методички |
| `UnsavedDocumentsDialog` | Таблица изменённых документов при выходе | Прямое требование QDialog и QTableWidget |

`main.cpp` создаёт QApplication, переводчик и главное окно, затем запускает
цикл событий. Интерфейс создаётся программно. Современный `connect`
проверяет типы сигналов и слотов при компиляции; в лекциях встречается
также старая запись через SIGNAL/SLOT.

QTabWidget владеет страницами, редактор — своим QTextDocument, документ —
подсветкой. Остальные модели и виджеты получают QObject-родителя.
`removeTab` не удаляет страницу: после успешного подтверждения она удаляется
явно. Стратегия передаётся как `unique_ptr<SyntaxSettingsReader>` в конструктор
окна и нужна во время загрузки настроек. Подмена стратегии показана в тестах.

Основной экземпляр документа — его QTextDocument: сигнал modificationChanged
обновляет `*` во вкладке и обозревателе. Не нужно отдельно синхронизировать
несколько флагов изменения. Путь меняется только после успешной записи.
`QSaveFile` дополняет простой QFile из лекции: commit заменяет оригинал
после успешной записи временного файла. Автоматического сохранения нет.

## Настройки подсветки

Исходник — `settings/syntaxes.xml`. CMake копирует его в `build/settings`.
Приложение читает файл относительно собственного exe, поэтому рабочий
каталог терминала не влияет на поиск. Для проверки без пересборки изменяйте
именно `build/settings/syntaxes.xml` и перезапускайте приложение.
Исходный файл сохраняйте отдельно: следующая сборка может обновить копию.

```xml
<settings>
  <syntaxes>
    <syntax id="example" name="Пример" ext_list="demo;example">
      <rule>
        <pattern value="\bHELLO\b"/>
        <format foreground="#00008B" font_weight="75"/>
      </rule>
    </syntax>
  </syntaxes>
</settings>
```

Добавлять язык нужно новым `syntax` внутри существующего `syntaxes`.
Расширения разделяются пробелом, `;` или `,`, регистр не учитывается,
начальная точка необязательна. Расширения и id должны быть уникальны.
Программа не содержит таблицы расширений C++ или встроенного списка его
ключевых слов. После «Сохранить как» подсветка выбирается заново.
Неизвестное расширение означает обычный текст без подсветки.

В `pattern value` записывается QRegularExpression. В XML обратный слеш
не удваивается, а кавычка внутри атрибута записывается как `&quot;`.
Дополнительный атрибут `end` задаёт конец многострочного правила:
`<pattern value="/\*" end="\*/"/>`.
Номер активного правила переносится между блоками через previousBlockState
и setCurrentBlockState. Строковые литералы защищены от распознавания
комментариев внутри них, например `"https://example.org"`.

Однопроходный поиск выбирает ближайшее совпадение; при одинаковом начале
приоритет имеет более позднее правило XML. Правила комментариев идут
после ключевых слов. Нулевая длина совпадения не зацикливает обработку.
Оформление задаётся foreground, необязательными font_weight и
font_italic="true". Значения веса до 99 интерпретируются по шкале Qt 5
из методички (50 — обычный, 75 — жирный); большие — по шкале Qt 6.

Отсутствующий или некорректный XML, неверный regex, цвет или вес шрифта
вызывают критическое сообщение. После него редактор работает без подсветки.
Частично прочитанные настройки не применяются. Второй производственный
формат не реализован: для добавления достаточно новой стратегии,
возвращающей те же SyntaxDefinition; само окно и подсветка не меняются.

## Сохранение и ограничения

- Текстовые файлы сохраняются в UTF-8; переключателя кодировок нет.
  Переводы строк проходят обычную нормализацию QTextEdit и текстового ввода-вывода Qt.
- Редактируется обычный текст, форматирование из буфера обмена не переносится.
- Повторное открытие одного пути переключает вкладку; одинаковые имена
  из разных каталогов разрешены. Полный путь показан в подсказке вкладки.
- «Сохранить как» не разрешает перезаписать документ, открытый в другой вкладке.
- «Сохранить все» сохраняет изменённые и новые документы по порядку вкладок.
  Отмена или ошибка останавливает операцию; уже сохранённые файлы не откатываются.
- «Закрыть все» проверяет вкладки последовательно; отмена останавливает закрытие.
  Уже закрытые до отмены вкладки не восстанавливаются.
- При выходе таблица содержит только изменённые документы. «Сохранить все»
  сохраняет их; «Не сохранять» разрешает выход; «Отмена» оставляет окно открытым.
  Отмена выбора имени и ошибка записи также отменяют выход, сохраняя все вкладки.
- Подсветка учебная, основана на regex: она не заменяет полноценный парсер C++;
  raw-строки и продолжения строк препроцессора отдельно не разбираются.
- Правила XML рассчитаны на светлый фон редактора, который фиксирован палитрой;
  остальные элементы следуют системной теме.

## Проверки и сценарий защиты

Qt Test проверяет чтение/запись кириллицы, сохранность состояния после ошибки,
вкладки и звёздочки, независимость документов, обработку XML и regex,
многострочные комментарии, комментарии внутри строк, замену стратегии,
добавление расширения из внешнего XML, смену подсветки после Save As,
сохранение всех документов, успешный выход, отмену выхода и файлового диалога,
ошибку записи при выходе, буфер обмена, док-панели, координаты курсора,
конфликт сохранения поверх открытого файла и работу при отсутствии настроек.
Тестовые файлы создаются только в QTemporaryDir.

Для защиты:

1. Запустить редактор. Показать QMainWindow: меню, четыре значка, две док-панели,
   вкладки и постоянные координаты курсора.
2. Открыть `examples/demo.cpp` и `examples/notes.txt`. Показать C++-подсветку,
   многострочный комментарий и отсутствие подсветки у txt. Ещё раз открыть
   demo.cpp — новая копия вкладки не появляется.
3. Изменить документ, увидеть `*` во вкладке и списке. Сохранить копию
   через «Сохранить как», увидеть исчезновение звёздочки и сообщение статуса.
4. Сохранить копию с расширением txt — подсветка исчезает. Вернуть cpp — появляется.
5. Продемонстрировать копирование, вставку, горячие клавиши, выбор документа
   в списке, открытие файла из проводника и скрытие панелей.
6. Создать два изменённых документа. Закрыть вкладку и выбрать «Отмена».
   Затем выйти: показать таблицу имён и расположений, отменить выход.
7. Повторить выход с «Сохранить все», отменить выбор имени: окно остаётся.
   Наконец сохранить документы и выйти.
8. Добавить пример языка выше в runtime XML, создать файл test.demo с HELLO,
   перезапустить редактор. Подсветка появляется без изменения C++ и пересборки.
9. Объяснить виртуальный интерфейс стратегии и распределение владения Qt.

Автоматические проверки запускаются командой из раздела «Быстрый запуск».

В автоматических проверках файловые диалоги заменены на Qt-диалоги
