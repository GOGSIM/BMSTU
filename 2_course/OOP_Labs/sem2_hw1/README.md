# Домашнее задание 1

## Потоки ввода-вывода и стандартная библиотека шаблонов

Вариант 2.

Цель домашнего задания - научиться работать с файловыми потоками C++,
последовательными и ассоциативными контейнерами STL, итераторами и стандартными
алгоритмами. Одинаковые действия необходимо выполнить несколькими способами,
чтобы показать разницу между обычной работой с потоками, итераторами и
алгоритмами STL.

## Быстрый запуск

Выполнить из каталога `sem2_hw1` в PowerShell:

```powershell
cmake -S . -B build
cmake --build build --config Debug
.\build\Debug\sem2_hw1.exe
```

## Как пользоваться программой

После запуска появляется главное меню:

- `1` — работа с последовательными контейнерами и файлами `input.txt`,
  `output.txt`;
- `2` — работа с товарами на складе;
- `0` — завершение программы.

### Если нужно создать случайные числа

1. В главном меню выбрать `1`.
2. Выбрать `1`, чтобы записать числа обычным файловым потоком, или `2`, чтобы
   использовать `generate`, `copy` и потоковый итератор.
3. В `input.txt` появятся 100 случайных целых чисел от -50 до 50.

### Если нужно обработать `input.txt` через контейнер

1. Сначала создать `input.txt` или поместить в него свои числа.
2. Выбрать контейнер: `3` — `vector`, `4` — `deque`, `5` — `list`.
3. Выбрать загрузку: `1` — обычный файловый поток, `2` — потоковые итераторы.
4. Выбрать обработку: `1` — функция контейнера, `2` — функция с итераторами,
   `3` — алгоритм `for_each`.
5. Выбрать вывод: `1` — обычный файловый поток, `2` — `copy` и
   `ostream_iterator`.

Результат записывается в `output.txt`. Для 100 исходных чисел файл содержит
102 значения: 100 результатов деления, сумму их абсолютных величин и среднее.

### Если нужна потоковая версия `transform`

1. Создать или подготовить `input.txt`.
2. В меню последовательных контейнеров выбрать `6`.
3. Программа прочитает файл потоковыми итераторами и сразу создаст
   `output.txt`.

### Если нужно работать со складом

В главном меню выбрать `2`. Дальше доступны команды:

- `1` — показать все записи;
- `2` — добавить товар;
- `3` — удалить товар по индексу;
- `4` — заменить товар, сохранив его индекс;
- `5` — найти товары по номеру склада;
- `6` — найти товары по коду;
- `7` — найти товары по дате поступления;
- `8` — найти просроченные товары на введённую дату;
- `9` — найти непросроченные товары на введённую дату;
- `10` — создать текстовую ведомость `warehouse_report.txt`;
- `0` — вернуться в главное меню.

При добавлении товара индекс назначается автоматически. Дата вводится отдельно:
день, месяц и год. Дробную цену следует вводить через точку, например `125.50`.
Основные записи находятся в бинарном файле `warehouse.dat`, поэтому его не
следует редактировать как обычный текст. Каждый поиск показывает результат на
экране и перезаписывает бинарный файл `search_results.dat`.

Чтобы вернуться из любого подменю, нужно выбрать `0`. При неправильном вводе
программа показывает сообщение и предлагает продолжить работу.

## Часть 1. Последовательные контейнеры

В качестве последовательных контейнеров используются вектор, двусторонняя
очередь и список.

Функция `createData()` должна создать текстовый файл `input.txt` и записать в
него 100 случайных целых чисел от -50 до 50. Необходимо реализовать две версии:

1. Запись данных с помощью файлового потока.
2. Заполнение вспомогательного контейнера алгоритмом `generate()` и запись его
   элементов алгоритмом `copy()` через потоковый итератор.

Шаблонная функция `loadData()` должна загрузить числа из файла в выбранный
последовательный контейнер. Необходимо реализовать две версии:

1. Чтение с помощью файлового потока.
2. Чтение с помощью потоковых итераторов и алгоритма `copy()`.

Для варианта 2 функция `modify()` должна разделить каждое число на полусумму
первого отрицательного и 50-го числа. Результаты деления хранятся как
вещественные числа. В конец результата добавляются сумма абсолютных величин
преобразованных элементов и их среднее арифметическое.

Необходимо предусмотреть четыре версии `modify()`:

1. Шаблонная функция, принимающая последовательный контейнер.
2. Функция, принимающая аргументы-итераторы.
3. Функция, использующая алгоритм `for_each()` и лямбда-функцию или
   функциональный объект.
4. Функция, использующая `transform()` и потоковые итераторы для одновременного
   чтения исходного файла, преобразования данных и записи результата.

Функция `outputResult()` должна записать контейнер-результат в `output.txt`.
Необходимо реализовать обычную запись файловым потоком и запись алгоритмом
`copy()` через потоковый итератор.

Для первой части требуется меню, позволяющее выбрать способ создания файла,
тип контейнера, способ загрузки, вариант обработки и способ вывода результата.

## Часть 2. Ассоциативные контейнеры

Индексный массив необходимо реализовать с помощью ассоциативного
контейнера-отображения. Для варианта 2 выполняется пункт 22 - учёт товаров на
складе.

Одна запись содержит номер склада, код и наименование товара, дату поступления,
срок хранения в днях, количество единиц и цену одной единицы товара.

Данные хранятся в бинарном файле. Программа должна поддерживать:

- первичный ввод записей с клавиатуры и добавление в файл;
- удаление и замену записи с помощью перезаписи исходного файла в новый;
- поиск по номеру склада;
- поиск по коду товара;
- поиск по дате поступления;
- поиск просроченных и непросроченных товаров относительно введённой даты;
- сохранение найденных записей в отдельный бинарный файл;
- преобразование бинарного файла в текстовую ведомость с общей стоимостью
  каждой позиции и итоговой стоимостью всех товаров.

Для второй части также требуется отдельное меню, демонстрирующее основные
операции программы.

## Основные требования

- Шаблонные функции не должны зависеть от конкретного типа данных. Тип элемента
  следует получать через типы контейнера, например `value_type`.
- Работа с файлами выполняется на основе потоковых классов C++.
- Ввод и вывод одной складской записи в бинарный файл выполняется целиком для
  объекта, а не отдельно для каждого поля.
- Решение должно использовать контейнеры, итераторы и алгоритмы STL и оставаться
  простым, соответствующим материалу лекций.

## Алгоритм проверки работоспособности

Перед проверкой нужно собрать и запустить программу по инструкции из раздела
«Быстрый запуск». Файлы `input.txt`, `output.txt`, `warehouse.dat`,
`search_results.dat` и `warehouse_report.txt` создаются в каталоге, из которого
запущена программа.

### Проверка первой части на случайных числах

1. В главном меню выбрать `1`, затем выбрать `1`. Программа должна создать
   `input.txt` обычным файловым потоком.
2. Проверить, что файл содержит ровно 100 целых чисел и каждое из них находится
   в диапазоне от -50 до 50. В PowerShell это можно проверить командами:

   ```powershell
   (Get-Content input.txt).Count
   $numbers = Get-Content input.txt | ForEach-Object { [int]$_ }
   ($numbers | Where-Object { $_ -lt -50 -or $_ -gt 50 }).Count
   ```

   Первая команда должна вывести `100`, последняя — `0`.
3. В меню первой части выбрать `3` для `vector`, загрузку `1`, обработку `1` и
   вывод `1`. После выполнения `output.txt` должен содержать 102 значения.
   Сохранить эталон командой `Copy-Item output.txt build\output_vector.txt`.
4. Повторить обработку с `deque`: пункт `4`, загрузка `2`, обработка `2`, вывод
   `2`. Команда ниже не должна ничего вывести:

   ```powershell
   Compare-Object (Get-Content build\output_vector.txt) (Get-Content output.txt)
   ```

5. Повторить обработку с `list`: пункт `5`, любая загрузка, обработка `3`, любой
   вывод. Снова выполнить `Compare-Object`: результаты должны совпасть.
6. Выбрать пункт `6`, чтобы проверить `transform` и потоковые итераторы.
   Получившийся `output.txt` также должен содержать 102 значения и совпадать с
   результатом контейнерных версий по проверке `Compare-Object`.
7. Выбрать пункт `2`, чтобы заново создать случайный файл через `generate`,
   `copy` и `ostream_iterator`. Ещё раз проверить количество и диапазон чисел.

Количество строк результата проверяется командой:

```powershell
(Get-Content output.txt).Count
```

Она должна вывести `102`. Последние две строки — сумма абсолютных величин 100
преобразованных чисел и их среднее. Если случайные числа дали нулевой делитель
или среди них нет отрицательного числа, программа должна вывести понятную
ошибку. В таком случае нужно повторно создать `input.txt`: это проверяет
обработку ошибки, а не означает поломку программы.

### Проверка второй части

Для чистой проверки следует сначала закрыть программу и удалить старые
`warehouse.dat`, `search_results.dat` и `warehouse_report.txt`, если данные в
них больше не нужны.

1. В главном меню выбрать `2`, затем добавить через пункт `2` три произвольные
   записи. Для воспроизводимой проверки можно использовать такие значения:

   | Склад | Код | Название | Дата | Срок | Количество | Цена |
   |---:|---:|---|---|---:|---:|---:|
   | 1 | 101 | Apples | 01.10.2026 | 30 | 10 | 120.50 |
   | 2 | 202 | Milk | 01.09.2026 | 7 | 5 | 90.00 |
   | 1 | 303 | Flour | 10.10.2026 | 365 | 2 | 80.00 |

2. Выбрать пункт `1`. На экране должны появиться три записи с уникальными
   индексами `1`, `2` и `3`.
3. Вернуться в главное меню, снова открыть склад и повторно выбрать пункт `1`.
   Все записи должны загрузиться из `warehouse.dat` после повторного входа.
4. Проверить поиски:
   - пункт `5`, склад `1` — две записи;
   - пункт `6`, код `202` — одна запись;
   - пункт `7`, дата `10.10.2026` — одна запись;
   - пункт `8`, контрольная дата `14.10.2026` — товар `Milk`;
   - пункт `9`, контрольная дата `14.10.2026` — товары `Apples` и `Flour`.
5. После каждого поиска должен перезаписываться бинарный файл
   `search_results.dat`, а количество найденных записей должно выводиться на
   экран.
6. Выбрать пункт `10` и открыть `warehouse_report.txt`. В нём должны быть три
   позиции, стоимость каждой позиции и строка `Grand total: 1815.00`.
7. Выбрать пункт `4`, заменить запись с индексом `2` и убедиться, что её индекс
   не изменился.
8. Выбрать пункт `3`, удалить запись с индексом `1`, затем проверить список и
   повторно запустить программу. Удалённая запись не должна появиться снова.
9. Попробовать удалить несуществующий индекс и ввести неправильную дату.
   Программа должна показать ошибку и продолжить работу без аварийного
   завершения.

После проверки текстовые и бинарные файлы можно удалить. Они перечислены в
`.gitignore` и не должны попадать в историю Git.
