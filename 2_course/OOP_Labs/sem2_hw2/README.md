# Домашнее задание 2

## Использование XML и модели-представления Qt

Учебное приложение на C++17 и Qt Widgets отображает XML с данными московского
общепита в виде иерархической таблицы. Требования взяты из методички ДЗ2;
модель и представление основаны на лекции 3, главное окно и меню — на лекции 4.

## Быстрый запуск из папки BMSTU

Если PowerShell открыт в корневой папке репозитория `BMSTU`, выполнить:

```powershell
.\2_course\OOP_Labs\sem2_hw2\run.ps1 -Demo
```

Команда сама соберёт приложение и откроет четыре XML-файла для демонстрации.
Переходить в папку ДЗ2 перед запуском не нужно.
Сценарий совместим с Windows PowerShell 5.1 и PowerShell 7. Файл `run.ps1`
сохранён в UTF-8 с BOM, чтобы Windows PowerShell корректно читал русские строки;
при редактировании эту кодировку нужно сохранять (она задана в `.editorconfig`).
Чтобы открыть пустое окно и выбирать файлы через меню, выполнить без `-Demo`:

```powershell
.\2_course\OOP_Labs\sem2_hw2\run.ps1
```

## Запуск из папки sem2_hw2

Открыть PowerShell в каталоге `sem2_hw2` и выполнить:

```powershell
.\run.ps1
```

Сценарий настроит CMake, соберёт приложение и откроет пустое окно.

Для открытия сразу четырёх демонстрационных файлов:

```powershell
.\run.ps1 -Demo
```

Для сборки и автоматических проверок без открытия окна:

```powershell
.\run.ps1 -Test -BuildOnly
```

По умолчанию используется установленный на этой машине комплект
`C:\Qt\6.12.0\mingw_64`, компилятор `C:\Qt\Tools\mingw1310_64` и Ninja.
Для другого размещения Qt передать параметры:

```powershell
.\run.ps1 -QtRoot 'D:\Qt\6.12.0\mingw_64' -QtTools 'D:\Qt\Tools'
```

В `QtTools` должны находиться `CMake_64`, `Ninja` и `mingw1310_64`.
Пути не записываются в системные настройки: сценарий временно меняет `PATH`
и восстанавливает его. Готовый exe находится в `build/sem2_hw2_xml_viewer.exe`;
рядом создаётся копия каталога данных. Для непосредственного запуска exe нужны
доступные через `PATH` DLL Qt и MinGW, поэтому удобнее пользоваться `run.ps1`.

## Как пользоваться

1. Выбрать «Файл → Открыть…» или нажать `Ctrl+O`. Диалог сразу показывает
   каталог `build/data` с четырьмя XML. Отмена ничего не меняет.
2. Открыть нужные файлы по очереди. Они добавляются в текущую вкладку.
3. Раскрыть стрелку у файла, затем у строки «Название организации».
   В столбце «Значение» находятся название, округ, район, адрес, телефоны и
   число мест. Узел «Геоданные» содержит широту и долготу.
4. Щёлкнуть правой кнопкой по имени файла: «Закрыть» удаляет его из дерева,
   «Переместить в новую вкладку» переносит документ целиком и активирует вкладку.
5. Перенос недоступен, если в **исходной вкладке** остался только один файл.
   На организациях, характеристиках и пустом месте контекстного меню нет.
6. «Файл → Закрыть все» очищает **все вкладки**, оставляя пустое «Общее дерево».
   «Файл → Выход» или `Ctrl+Q` закрывает приложение.

Пустая дополнительная вкладка удаляется при закрытии последнего её документа.
Основная вкладка сохраняется. Повторное открытие того же полного пути активирует
прежний документ; одинаковые имена файлов из разных каталогов допустимы.
Операции «Закрыть» и «Закрыть все» меняют только содержимое окна: файлы на диске
не изменяются. Приложение предназначено для чтения, редактирование отключено.

## Данные и ограничение формата

В `data/` находятся четыре XML с реальными записями:

| Файл | Записей |
| --- | ---: |
| `cafes.xml` | 448 |
| `coffeehouses.xml` | 45 |
| `bars.xml` | 131 |
| `fast_food.xml` | 15 |

Из-за недоступности портала и серверов экспорта использован согласованный
вариант: преобразование доступной CSV-копии части набора общепита Москвы.
Это **не оригинальные XML, скачанные с портала**, и дата исходной копии
неизвестна. Выборка кофеен сделана по названию и пересекается с другими
категориями. Полное происхождение, ссылки, правила отбора и структура XML
описаны в [data/README.md](data/README.md); контрольная сумма — в
[data/provenance.json](data/provenance.json).

Поддерживается известная структура `<catering><organization>…`, а не любой
произвольный XML. Это соответствует разрешению методички считать структуру
файла известной. Пустой набор допустим; отсутствующие поля отображаются как
«Нет данных», число мест `0` сохраняется. Все номера телефонов выводятся через
точку с запятой. Ошибки чтения, синтаксиса и структуры показываются критическим
сообщением, а уже открытые документы остаются в дереве.

Для повторного получения XML из сохранённого источника нужен только Python
3.9+ со стандартной библиотекой. Python не участвует в работе приложения:

```powershell
python tools/prepare_data.py data/source/places.csv `
  --source-url 'https://github.com/SergUSProject/BigDataProc_HomeWorks/blob/1c098ebd31d106d98c7d703ce4c09b3f26d98fef/spark/data/places.csv' `
  --dataset-date 'не указана в исходной копии'
```

## Архитектура и связь с лекциями

| Часть | Класс и назначение | Основание |
| --- | --- | --- |
| Приложение | `QApplication` и цикл `exec()` | Прошлая лабораторная, лекция 5, слайды 3–8 |
| Главное окно | `MainWindow : QMainWindow` | Лекция 4, слайды 3–7 |
| Меню и диалоги | `QMenu`, `QAction`, `QFileDialog`, критическое сообщение | Лекция 4, слайды 23, 39–51; требования ДЗ2 |
| Модель | `XmlTreeModel : QStandardItemModel` | Лекция 3, слайды 25–40, 46–54 |
| Представление | `QTreeView` с вложенными двухколоночными строками | Лекция 3, слайды 38–40 |
| Вкладки | `QTabWidget`, в каждой вкладке своя модель и дерево | Требование ДЗ2 |
| XML | `QDomDocument` внутри модели | Требование DOM из методички |

В лекции 6 рассматривается Qt Quick/QML. Здесь требуются именно `QTreeView`,
`QMenu` и `QTabWidget`, поэтому интерфейс написан на C++ с Qt Widgets.
В приложенных лекциях API DOM подробно не разобран; для обязательного DOM
используется документация [QDomDocument](https://doc.qt.io/qt-6/qdomdocument.html)
и принцип чтения из [примера DOM Bookmarks](https://doc.qt.io/qt-6/qtxml-dombookmarks-example.html).

`main.cpp` создаёт приложение и окно. `MainWindow` обрабатывает действия
пользователя и выбирает нужную вкладку. `XmlTreeModel` читает XML и строит
данные; окно не разбирает теги, а модель не создаёт диалогов.

`QStandardItemModel` — потомок `QAbstractItemModel`. Он уже реализует поиск
индексов, родительские связи и выдачу данных представлению, поэтому повторять
эти методы вручную не нужно. В модели есть обязательный конструктор
`XmlTreeModel(const QString& fileName, QObject* parent = nullptr)` и метод
`appendFile()` для добавления следующих документов.

Сначала `QFile` открывает файл, затем `QDomDocument::setContent()` создаёт DOM.
После проверки структуры модель формирует строки файла, организаций,
характеристик и координат. Подготовленный корень добавляется только в конце:
ошибка загрузки не очищает ранее открытые данные. В Qt 6.5+ результат разбора
`ParseResult` содержит сообщение, строку и столбец ошибки.

## Владение объектами и перенос

`MainWindow` владеет `QTabWidget`; вкладки владеют деревьями, а каждое дерево
является `QObject`-родителем своей модели. Модель владеет `QStandardItem`,
а элементы владеют своими дочерними строками. Это две связанные иерархии:
иерархия объектов интерфейса и иерархия данных модели.

До добавления корня в модель он находится в `std::unique_ptr`. Этот указатель
автоматически удалит незавершённое поддерево при выходе из функции.
После `release()` владельцем становится модель; вручную удалять корень нельзя.

`removeRow()` удаляет строку с её потомками. Для переноса используется
`takeRow()`: он извлекает строку **без удаления**. `appendRow()` передаёт её
новой модели вместе с потомками и служебными ролями. Поэтому XML не читается
повторно и закрытие исходной вкладки не уничтожает перенесённые элементы.
`removeTab()` не удаляет страницу автоматически — после извлечения страницы
окно явно вызывает `delete`, что также удаляет её модель.

## Конструкции C++ и Qt для защиты

- `public QStandardItemModel` означает наследование. `explicit` запрещает
  неявное создание модели из аргумента; `nullptr` обозначает отсутствие родителя.
- `Q_OBJECT`, `signals/slots` и `connect` связывают объекты через метаобъектную
  систему Qt. CMake `AUTOMOC` запускает генерацию нужного служебного кода.
- `const QString&` передаёт строку по ссылке без копирования и запрещает её
  менять через этот аргумент. `const` после метода запрещает менять объект.
- `QModelIndex` адресует ячейку: строку, столбец и родительский узел. У корня
  файла индекс валиден, а `parent()` невалиден. Проверяется именно строка,
  по которой щёлкнули, а не ранее выделенный документ.
- `Qt::UserRole + 1` хранит полный путь отдельно от видимого имени файла.
  Это позволяет различать одинаковые имена в разных каталогах.
- `qobject_cast` безопасно проверяет тип `QObject`; `sender()` возвращает
  отправителя сигнала, чтобы один слот мог обслуживать несколько деревьев.
- `QStringLiteral` создаёт строковый литерал Qt, `tr()` помечает видимый текст
  как переводимый, а `arg()` подставляет значения вместо `%1`, `%2` и т. д.
- Безымянный `namespace` ограничивает вспомогательные функции одним `.cpp`.
  Делегирующий конструктор вызывает другой конструктор того же класса.
- `std::unique_ptr` выражает единственное владение ресурсом. Его `release()`
  используется только при передаче владения модели Qt.

## Проверки

Проверено на Windows с Qt 6.12.0: приложение собирается; Qt Test сообщает
`18 passed, 0 failed, 0 skipped` (включая начальную и завершающую проверки).
Запуск сценария из корня `BMSTU` со сборкой, тестами и демонстрацией также
проверен в Windows PowerShell 5.1. Синтаксический разбор `run.ps1` проходит
без ошибок в Windows PowerShell 5.1 и PowerShell 7.

На Windows дополнительно выполняется `windows_responsiveness_tests`:
он запускает настоящий exe с четырьмя XML, читает его интерфейс отдельным
COM-клиентом UI Automation, проверяет ответы окна и процессорное время
при десятисекундном простое, затем проверяет обычное закрытие окна.
Это дополняет offscreen-тесты, в которых системный мост Windows отсутствует.

Автоматически проверяются DOM-разбор, UTF-8 и XML-экранирование, вложенность,
несколько телефонов, отсутствующие значения и ноль мест, пустой набор,
повреждённый XML, неверная структура, отсутствующий файл, сохранение ранее
открытых данных, все четыре файла поставки, одинаковые имена и повторные пути,
перенос без повторного чтения, удаление моделей, глобальная очистка,
контекстное меню только у корней в обоих столбцах и критический диалог ошибки.
Предупреждения offscreen-плагина о `raise()` и захвате клавиатуры ожидаемы:
тесты запускают меню без обычного экранного окружения.

Вручную в окне проверены раскрытие полей, читаемость кириллицы и длинного
адреса, меню корня, перенос во вторую вкладку и стандартный файловый диалог
с отменой без потери документов. Все значения четырёх XML отдельно сверены
с CSV, включая телефоны, координаты и идентификаторы.

## Обход зависания Windows UI Automation

На этой машине окно с Qt 6.12.0 периодически переставало отвечать даже без
действий пользователя. В двух снятых стеках зависших процессов главный поток
находился в `UIAutomationCore.dll`; один из стеков также проходил через
провайдер `qwindows.dll` и вычисление геометрии виджета. Это отдельная проблема
взаимодействия Qt с системными клиентами доступности, а не ошибка DOM-разбора.

`WindowsAccessibilityGuard` устанавливается в `main.cpp` до создания окна.
Через публичный механизм `QAbstractNativeEventFilter` он отвечает нулём на
`WM_GETOBJECT`, не передавая запрос проблемному COM-провайдеру Qt. Остальные
события продолжают обрабатываться Qt. Фильтр действует только в процессе этого
приложения на Windows; системные настройки и другие программы не меняются.

Ограничение обхода: экранные дикторы и средства UI Automation видят стандартное
описание окна, но не подробное содержимое дерева Qt. Навигация клавиатурой,
мышь, меню, файловый диалог и вкладки продолжают работать. На других ОС фильтр
ничего не перехватывает. Чтобы явно вернуть штатный мост, например для проверки
на исправленной версии Qt/Windows или работы с экранным диктором:

```powershell
$env:SEM2_HW2_NATIVE_ACCESSIBILITY = '1'
.\2_course\OOP_Labs\sem2_hw2\run.ps1 -Demo
```

Этот режим может вернуть исходное зависание на проблемном окружении.
Для возврата к защищённому режиму перед следующим запуском:

```powershell
Remove-Item Env:SEM2_HW2_NATIVE_ACCESSIBILITY -ErrorAction SilentlyContinue
```

После исправления проверены запросы настоящего клиента UI Automation,
простой, раскрытие характеристик и перенос документа во вкладку. Основной
DOM-код и структура модели остались прежними: дополнительный фильтр относится
только к системным событиям Windows.

Для самостоятельной демонстрации запустить `run.ps1 -Demo`, раскрыть кафе и
геоданные, перенести файл в новую вкладку, проверить недоступность повторного
переноса единственного документа и выполнить «Закрыть все». Ошибку можно
проверить на отдельном временном XML с незакрытым тегом: сообщение должно
содержать имя файла, строку и столбец, а прежние документы — остаться в окне.

## Сборка через CMake без сценария

Использовать C++17 и Qt 6.5+, модули Widgets и Xml; для тестов нужен Qt Test.
При настроенном окружении своего комплекта Qt:

```powershell
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH='C:/Qt/6.12.0/mingw_64'
cmake --build build
ctest --test-dir build --output-on-failure --timeout 45
```

Компилятор должен соответствовать комплекту Qt; `run.ps1` выбирает его явно.
Без тестов проект настраивается с `-DBUILD_TESTING=OFF`. Сборочные результаты
и локальные настройки редактора исключены из Git.
