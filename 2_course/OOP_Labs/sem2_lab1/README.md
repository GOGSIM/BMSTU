# Лабораторная работа 1

## Разработка конечно-элементного загрузчика сетки

Репозиторий предназначен для выполнения лабораторной работы по курсу
«Основы программирования на C++». Основная задача - разработать загрузчик
конечно-элементной сетки, который читает файл формата `.aneu`, сохраняет данные
в объекте `Mesh` и предоставляет набор операций поиска и модификации сетки.

Требования ниже переписаны по файлу задания
`Семестр_2_ЛР_1_Разработка_КЭ_загрузчика_сетки.docx`. Разделы с рекомендациями
по реализации основаны на лекции
`Семестр_2_Лекция_1_STL_Контейнеры.pdf` и не заменяют формальное ТЗ.

## Цель работы

Разработать конечно-элементный загрузчик сеток с потенциальной возможностью
поддержки разных форматов файлов КЭ-сеток. В рамках этой лабораторной
обязательна поддержка формата `.aneu`.

## Обязательная архитектура

### `MeshLoader`

Базовый класс загрузчиков сетки.

Обязательные требования:

- объявить чисто виртуальный метод `loadMesh`;
- использовать этот класс как общий интерфейс для загрузчиков разных форматов;
- результатом работы `loadMesh` должен быть объект `Mesh`.

### `AneuMeshLoader`

Производный класс от `MeshLoader`.

Обязательные требования:

- переопределить метод `loadMesh`;
- обеспечить загрузку сетки из файла формата `.aneu`;
- читать файл через файловые потоки C++ (`IOStream`);
- обрабатывать ошибки загрузки через исключения.

### `Mesh`

Класс для хранения данных сетки и операций над ней.

Обязательные требования:

- хранить узлы сетки;
- хранить объемные конечные элементы;
- хранить граничные конечные элементы;
- предоставлять методы доступа к STL-контейнерам с этими данными;
- предоставлять методы поиска, построения соседства и вставки новых узлов.

## Вспомогательные типы данных

В отдельном заголовочном файле необходимо создать вспомогательные типы данных
для класса `Mesh`.

### `Node`

Тип данных «узел».

Должен хранить:

- `ID` узла, значение не меньше `1`;
- декартовы координаты узла;
- флаг, определяющий, является ли узел вершиной конечного элемента или
  внутренним узлом.

### `FiniteElement`

Тип данных «конечный элемент».

Должен хранить:

- `ID` конечного элемента, значение не меньше `1`;
- `ID` геометрической области, которой принадлежит элемент по данным файла
  сетки;
- список `ID` узлов конечного элемента.

Для объемного КЭ геометрическая область может быть, например, идентификатором
объема. Для граничного КЭ геометрическая область может быть идентификатором
грани или поверхности.

## Обязательные методы `Mesh`

Класс `Mesh` должен предоставлять следующие операции.

### Доступ к данным

- Получить STL-контейнер узлов.
- Получить STL-контейнер объемных конечных элементов.
- Получить STL-контейнер граничных конечных элементов.

### Поиск элементов

- Вернуть контейнер `ID` тетраэдральных КЭ по `ID` трех вершинных узлов.
  Для этого по ТЗ нужно использовать алгоритм `std::find_if` и создать
  необходимый предикат.
- Вернуть контейнер `ID` тетраэдральных КЭ с общим ребром, заданным через
  `ID` двух узлов.
- Вернуть контейнер `ID` граничных узлов по `ID` границы геометрической модели,
  на которой они лежат.
- Вернуть контейнер `ID` тетраэдральных КЭ с заданным `ID` области, в которой
  они лежат.
- Вернуть контейнер `ID` граничных КЭ с заданным `ID` границы, на которой они
  лежат.

### Соседство узлов

Создать контейнер, в котором `n`-й элемент хранит контейнер из `ID` всех узлов,
соседних по ребрам с узлом `n`.

Важно: поскольку `ID` узлов начинаются с `1`, нужно явно решить, как
соотносить `ID` узла и индекс контейнера. Например, можно хранить пустой
нулевой элемент или выполнять преобразование `index = id - 1`.

### Вставка узлов в середины ребер

Реализовать метод, который вставляет новые узлы в середины ребер существующих
КЭ, включая граничные КЭ.

Метод обязан учитывать:

- обновление списков узлов каждого объемного КЭ;
- обновление списков узлов каждого граничного КЭ;
- добавление новых узлов в общий список узлов сетки;
- ситуацию, когда одно ребро является общим для нескольких КЭ и новый узел в
  середине такого ребра должен создаваться один раз.

### Форматированный вывод

Необходимо реализовать отформатированный вывод:

- `Node` в заданный поток;
- `FiniteElement` в заданный поток.

Удобный вариант реализации - перегрузить `operator<<` для обоих типов.

### Дополнительные методы

По ТЗ можно добавлять другие вспомогательные методы и типы данных, если они
нужны для чистой реализации.

## Основные требования из ТЗ

- Для чтения файла сетки использовать файловые потоки C++ (`IOStream`).
- Предполагается, что количество узлов и элементов в сетке очень велико.
- Сложность каждого обязательного метода должна быть минимальной и меньше
  `O(n^2)`.
- Методы должны быть реализованы на основе контейнеров, итераторов и алгоритмов
  STL.
- Использование ручных циклов должно быть сведено к минимуму.
- Ошибки и нештатные ситуации загрузки сетки нужно обрабатывать через
  исключения.
- При необходимости можно разработать иерархию исключений.

Примеры исключительных ситуаций:

- файл сетки не найден;
- файл не удалось открыть;
- неверный формат файла сетки;
- некорректное количество узлов или элементов;
- ссылка элемента на несуществующий `ID` узла;
- `ID` узла или элемента меньше `1`;
- неожиданный конец файла.

## Консольный запуск

Программа должна поддерживать запуск бинарного файла из консоли с передачей
имени загружаемого файла через параметры командной строки.

Пример ожидаемого сценария:

```bash
mesh_loader path/to/mesh.aneu
```

Если имя файла не передано или файл некорректен, программа должна сообщить об
ошибке и завершиться без неопределенного поведения.

## Формат файла `.aneu`

Формат `.aneu` получается из файла `.neu` ручным добавлением размерностей в
строки с количеством объектов.

Общий вид файла:

```text
<Количество узлов> <Размерность пространства>
X1 X2 X3
...
X1 X2 X3
<Количество КЭ> <Количество узлов в одном КЭ>
<ID материала> N1 N2 N3 N4
...
<ID материала> N1 N2 N3 N4
<Количество поверхностных КЭ> <Количество узлов в одном поверхностном КЭ>
<ID поверхности> N1 N2 N3
...
<ID поверхности> N1 N2 N3
```

Обозначения:

- `Xi` - координата узла;
- `Ni` - `ID` узла;
- `Ni` должен быть числом от `1` до `<Количество узлов>`;
- для объемного тетраэдрального КЭ в задании используется `4` узла;
- для поверхностного граничного КЭ в задании используется `3` узла.

## Формат файла `.neu`

Исходный формат `.neu` имеет вид:

```text
<Количество узлов>
X1 X2 X3
...
X1 X2 X3
<Количество КЭ>
<ID материала> N1 N2 N3 N4
...
<ID материала> N1 N2 N3 N4
<Количество поверхностных КЭ>
<ID поверхности> N1 N2 N3
...
<ID поверхности > N1 N2 N3
```

Чтобы вручную преобразовать `.neu` в `.aneu`, нужно:

- изменить расширение файла на `.aneu`;
- в строку с количеством узлов добавить размерность пространства;
- в строку с количеством объемных КЭ добавить количество узлов в одном КЭ;
- в строку с количеством граничных КЭ добавить количество узлов в одном
  граничном КЭ.

## Генерация сетки в NetGen 5.3

Сетки формата `.neu` могут быть сгенерированы в NetGen.

Порядок действий:

1. Создать файл `.geo` по примерам из NetGen.
2. Открыть `.geo` в NetGen через `File -> Load Geometry`.
3. При необходимости настроить сетку через `Mesh -> Meshing Options`, вкладки
   `General` и `Mesh Size`.
4. Нажать `Generate Mesh`.
5. Выбрать `File -> Export Mesh`.
6. Сохранить файл в формате `.neu`.
7. Вручную преобразовать `.neu` в `.aneu`.

Ссылки:

- NetGen: [http://sourceforge.net/projects/netgen-mesher/](http://sourceforge.net/projects/netgen-mesher/)
- NetGen 5.3: [https://sourceforge.net/projects/netgen-mesher/files/netgen-mesher/5.3/](https://sourceforge.net/projects/netgen-mesher/files/netgen-mesher/5.3/)

## Рекомендации по реализации в стиле лекции STL

Эти пункты не являются отдельными требованиями ТЗ, но помогают написать код в
стиле лекции и выполнить требование об использовании STL.

- Для хранения последовательностей узлов и элементов использовать
  `std::vector`: нужен быстрый доступ по индексу, а размер можно заранее
  зарезервировать после чтения количества объектов.
- Перед массовым добавлением элементов вызывать `reserve`, чтобы уменьшить
  число перевыделений памяти и не инвалидировать ссылки/итераторы без
  необходимости.
- Для быстрых поисков по `ID` и ребрам использовать ассоциативные структуры:
  `std::unordered_map`, `std::unordered_set`, `std::map` или `std::set`, если
  нужен упорядоченный результат.
- Для ключа ребра хранить пару узлов в нормализованном виде:
  `(min(nodeA, nodeB), max(nodeA, nodeB))`. Это позволит считать ребра
  неориентированными и не создавать дубликаты срединных узлов.
- Для методов, которые только читают данные, возвращать `const`-ссылки на
  контейнеры, чтобы не копировать большие сетки.
- Использовать `empty()` вместо сравнения `size() == 0`.
- Использовать `at()` там, где нужен контролируемый выход за границы с
  исключением `std::out_of_range`.
- Использовать `cbegin()` и `cend()` для чтения контейнеров без модификации.
- По возможности применять стандартные алгоритмы: `std::find_if`,
  `std::copy_if`, `std::transform`, `std::for_each`, `std::all_of`,
  `std::any_of`, `std::sort`, `std::unique`.
- Для предикатов использовать отдельные функциональные объекты или лямбда-
  выражения с понятными именами.
- Минимизировать ручные циклы, но не жертвовать читаемостью и корректностью
  алгоритма.
